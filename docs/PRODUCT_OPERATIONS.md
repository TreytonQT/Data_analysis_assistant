# 产品经营：SKU诊断与价格追踪

本文件描述2026-11-17用户确认的完全重建方案及当前实现，替代同日早期“把旧页面重新分组”的设计。

## 页面与任务

产品经营只有经营诊断、涨价追踪、降价追踪三个侧栏入口；变体管理为独立一级入口。诊断页内部切换积压清仓、利润风险、新品低销，均为一行一个SKU的处理队列。新页面不再嵌入旧产品矩阵、促销板或新品页面。

- 积压清仓默认90天以上有库存、占用资金倒序。90／180／365天筛选同时改变入选SKU、库存和资金总额，分别对应原始91天、181天和366天起的库龄段。停止店铺按原配置规则从可处理清仓范围排除，完整库存事实仍在详情保留。
- 清仓在库龄库存后展示可排序的日均销量、可售天数。两项始终按本行SKU全部运营记录计算，包含全部库龄及停提款店铺，不随库龄或开发员筛选缩减，不引入同ASIN其它SKU。默认仍按占用资金倒序；指标空值在升降序均排后。
- 利润档位为＜0%、[0%,5%)、[5%,12%)、[12%,20%)、≥20%，缺失独列，默认前四档；清空表示全部。保留少于5单的站点，主行显示小样本站点数；最少销量默认为0。主行显示命中站点最差毛利、命中销售额及毛利润，不按国家重复计库存。各SKU＋ASIN＋国家毛利按汇总毛利润÷汇总销售额计算，不平均毛利率。低毛利不自动产生降价建议。
- 新品为首次到货开售后0～99天，默认可售库存大于0且90天销量小于5，支持全部新品、零单及自定义范围。下限包含、上限不包含；缺失或非法负销量不当作零单。默认销量升序、开售天数降序；不足7天为观察期。覆盖天数为可售库存÷日均销量，已知零日销且有库存显示∞，未知仍为横线。

共同筛选为开发员及品名／SKU／全部关联ASIN搜索。筛选草稿只有确定、搜索只有提交后才请求。筛选、源版本变化清理旧勾选；同一范围跨页保留勾选。复制只复制所选SKU；导出有勾选时为所选、无勾选时为全部匹配，均不限当前分页。导出携带源版本，过期返回409要求刷新重选。

## SKU分析模型与来源

`backend/product_operations.py`将运营、毛利、领星、首次到货、图片和销量历史关联到统一SKU身份，按NFKC、去空白、大写匹配。库存事实只从原运营行汇总，同一物理记录仅人员／名称元数据不同不重复计入；多个ASIN的实际库存行仍各计一次。财务／Listing关联不会扩展库存行。仅财务中存在的SKU仍保留利润证据，库存显示未知。

| 来源 | 用途与粒度 |
| --- | --- |
| 运营原始表 | SKU库存、库龄资金、90天销量、可售覆盖，保留上传时间 |
| 毛利原始表 | SKU＋ASIN＋国家财务；沿用FBA销售额至COD物理区间、广告净额先汇总后取绝对值；保留报告起止日 |
| 领星产品监控表 | 实际总价、币种、评分、逐日观察事件；使用已上传的标准化快照 |
| 首次到货SQLite记录 | 开售日期及新品天数；无有效日期不纳入新品 |
| 最新销量明细＋往月销量及其索引 | 精确站点每日销量、当前7／30天窗口及趋势历史 |
| 图片表 | 沿用MSKU＋ASIN或本地SKU对应关系及共享预览 |
| 店铺配置 | 清仓和弃置参考的停止店铺排除 |

库存、财务、销量及价格分别带来源周期，库存／财务附完整性状态和缺失字段数量。缺少可选源只影响相应证据；缺失资金不汇总成虚假的完整总额。销售额明细、月业绩仍服务原经营和部门报表，不替代SKU毛利或销量。

详情中的计提参考沿用原库龄系数；弃置参考沿用“对应库存×6＋对应资金×1.5”，90／180／365天作为独立测算参数，切换不改变诊断清单。界面金额为人民币万元，导出金额为元；站点价格保留原币种，比例导出为原比例。

### 清仓补货口径指标（2026-11-18）

- 上架天数使用运营表“上架时间”，复用补货日期解析；不使用首次到货日期。逐条去重后的原运营记录校准，再在SKU内严格汇总。上架0～89天：7天销量÷7×90%＋14天销量÷14×9%＋30天销量÷30×1%；第90天起：对应权重60%／30%／10%。
- 补货口径总库存＝可售＋待调仓＋调仓中＋待入库×2＋采购在途＋本地库存＋在途＋计划入库。可售天数＝本SKU总库存÷本SKU校准日均销量。待入库计两次，沿用现行补货公式。
- 日均只要求有效上架日期和7／14／30天销量，不因缺重量或库存组成阻断。任一成员缺必需输入则该项汇总未知；可售天数还要求库存组成全部完整、汇总日均大于0，不用部分记录冒充完整结果。
- 已知日均0显示0、可售天数未知；库存0且日均为正时显示0天。数值最多两位小数，正日均小于0.01显示“＜0.01”，计算和排序保留原精度。数值支持鼠标和键盘提示，可售天数提示展示库存分子；窄桌面在表内横向滚动。
- 分析模型及API字段为`clearance_daily_units`、`clearance_total_stock`、`clearance_available_days`。清仓CSV追加“日均销量（补货口径，单/天）”“可售天数（补货口径，天）”“补货口径总库存（件）”；一行一个SKU，沿用选中／筛选／版本范围。
- `daily_units`、`coverage_days`仍为原运营日均与可售覆盖，不改变新品视角；补货原有异常判断（含重量等）保留。两处共用小型纯函数，无数据库迁移。
- 使用隔离虚构运营／财务样本及诊断接口、生产构建验证深浅主题四种桌面宽度及交互；公开项目不包含业务原表、验收导出或本机报告。

## 价格与销量趋势

买家实际总价比较相邻快照，前后须为正数且同币种，差额超过0.01才是实际变价。完整保留期内先按SKU＋ASIN＋国家选最新实际变价，再筛方向、日期和幅度。按未四舍五入的绝对幅度每5个百分点归档，首档(0%,5%)，其余左闭右开，Decimal避免恰好5%错档。

T＝近7天销量÷7－近30天销量÷30，表示当前销量趋势，不是变价带来的因果增量。精确SKU＋ASIN＋国家匹配，无ASIN回退。截止日为销量源最大日期与北京时间昨天较早者；往月提供完整日期，最新明细按精确身份和日期优先：已知值（包括0）覆盖往月，缺失单元格或缺失身份改查往月，不跨SKU／ASIN／国家填充。完整窗口才能计算T。

1440桌面左侧可点击幅度分布，右侧SKU销量排名；1024分布移至上方横排。分布显示记录数、销量升／降／平／缺失及平均T，点击筛选时保留其他档位上下文。默认展示截至最新快照的近30天变价，日期可调整。默认按|T|倒序，另有销量上升最多、下降最多；缺失置后。分别显示涉及SKU数和站点记录数，清单按站点导出，不含可重复累计的库存资金。


### 跨源销量补充（2026-11-17用户追加确认）

1. 最新日销量明细优先，精确SKU＋ASIN＋国家＋日期缺失时查往月销量；已知0不覆盖，图表与窗口求和使用相同规则。没有最新明细时仍可使用可关联的往月源，显示其实际截止日。
2. 仍缺7天或30天总量时，可用毛利原始表的销量，但必须SKU＋ASIN＋国家完全相同，报告起止日恰好等于所需7／30天窗口，且销量非负有限。已知明细值不覆盖，未来变价待更新规则保留；标注“毛利原始表（同N天周期）”。
3. 当前运营原始表无国家列，单行合并多国店铺，7／30天销量属于SKU跨国汇总。用户确认使用独立的“SKU汇总参考”，不改成国家销量，不计入站点T排名、平均T或销量升降分类。参考保留原表7／30天口径及上传快照，不与不同时段的站点值混算。
4. 列表在站点不足时展示SKU总量及参考T，详情常驻7／30天汇总参考，导出分别标明站点窗口来源与SKU参考字段。汇总值不能摊成每日销量，日历史仍仅使用实际日记录；实在没有证据的字段仍为未知。

缓存签名升至price-monitor-v4，避免复用旧的整日覆盖结果。站点T与SKU参考分别标注来源，缺完整证据时保持未知，不以0填充。

## 统一详情

`components/SkuDetailsDrawer.tsx`由诊断、涨价和降价三个入口共用，关闭保留列表筛选、勾选和滚动。产品身份列出全部ASIN、开发员及图片；库存与各国经营分开展示，并标出各自数据周期。

趋势按精确ASIN＋国家选择30／90／180天，销量与实际价格分图、共用日期范围。未观察日期断线，不插值、不补零；价格图标注实际观察到的变价日期，跨快照间隔不代表准确改价时间。图表沿用共享Portal浮层及键盘方向键、Home／End／Esc。

历史包含实际总价变动、已有长期调价、促销和最近登记快照。已下架SKU及旧ASIN仍可按精确站点进入历史，标明“仅历史观察”；不把旧价当当前价。人工历史只读展示，原API及表保留。新主流程通过复制／导出衔接用户ERP操作，不自动提交ERP改价或促销。

## 接口、版本与兼容

新增接口前缀`/api/product-operations`：

- `GET /workbench`：诊断筛选、排序、汇总、来源和分页，默认50、最大200。
- `POST /export.csv`：相同筛选、可选SKU集合及源版本，一行一个SKU，各国财务和价格为分国／ASIN明确字段，不重复输出库存。
- `GET /skus/{sku}`：统一详情、库龄与历史；SQLite通过只读连接读取，不初始化业务库。
- `GET /skus/{sku}/series`：精确ASIN＋国家、30／90／180天稀疏观察序列。
- `GET /prices`及`GET /prices/export.csv`：复用可靠价格事件／T计算，附中文名、风险和来源；默认30、最大200。

库存、财务及元数据按文件签名和业务日缓存，读取期间源变化有限重试后返回409；相邻价格事件继续缓存。前端保留active、版本刷新、请求取消与旧响应保护，导出有重复触发锁。

旧`page=products&tab=low-margin`映射利润风险，`page=new-products`映射新品，旧产品／滞销／促销映射经营诊断，旧实际价格入口映射涨价追踪。旧快捷标签迁移为规范入口并去重；变体与其他模块业务口径不变。原产品、促销、调价及观察API继续兼容。

价格原表和标准化快照保留180个日历日，同日替换和回滚语义保持。旧历史无法自动补回；页面显示实际快照起止范围。真实180天满量性能未作无数据推断。

## 验收

测试必须先隔离data、config、SQLite和TEMP，不以真实环境导入backend.main。测试／构建单条85秒硬截止；浏览器使用隔离接口和样例验证界面，不能将样例验收描述为全部真实业务数据验收。

内部验收目录、业务数量和交接记录不随源码或发布包公开；缺少的历史数据不会自动补回。
