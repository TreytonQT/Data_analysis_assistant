# 领星产品监控表与变体管理

独立一级的“变体管理”使用最新日期的领星Listing原表。上传入口仍接受原来的文件名及格式，价格监控继续按原口径工作。新增父ASIN、变体属性不是旧售价文件的必填列；旧原表缺列时变体页提示上传新格式。旧标准化CSV丢弃过新字段时，从对应原文件只读恢复，不回写原文件或要求重传。

## 分组与显示

- 先排除VMP_…_2_PK虚拟2件装，再按店铺分别构建关系；同店内逐行排除父ASIN为空或等于子ASIN的数据。相同父ASIN归组；父体共享子ASIN时跨国家、传递合并。搜索和分页在分组完成后执行，命中任一子体仍保留完整组。
- 页面每店每组独立一行，仅显示该店至少两个不同子ASIN的组；同一子ASIN的多个MSKU不增加变体数。暂时隐藏的单ASIN组保留原父SKU记录，后续重新满足条件时继续匹配。
- 子体按MSKU＋ASIN一行，国家、父ASIN、变体属性保留原对应关系和语言。运营数据不匹配时仍显示该子体，销量缺失保留null。
- 子体品名取运营原始表的`本地SKU名称`，完整原文保留。已合成组通用品名取最高日均销量子体的完整原品名，并列按MSKU、ASIN排序；最高销量子体缺名时按销量顺延，缺销量子体排在已知销量之后，全组缺销量时按MSKU、ASIN取首个有名子体。全部缺名显示“品名待归纳”。不以多语言Listing长标题替代内部中文品名。
- 日均销量取运营原字段，按MSKU＋ASIN汇总，国家关系不会重复累计。父图取最高日均销量子体，平手按MSKU、ASIN排序；代表SKU无图或全组缺少销量时占位。子图继续复用既有图片映射规则。
- 搜索支持品名、父SKU、父ASIN、子ASIN、MSKU，变体状态筛选提供全部状态／已填写／未填写／待合成，并可组合多个开发员；开发员命中任一子体即显示完整组及全部子体。未填写仅包含已有真实父ASIN且父SKU状态为未填写的组，排除未合成组及父SKU待确认组；待合成按relation_kind=unassembled筛出所有未合成组，不受父SKU已填写／未填写／待确认影响；保存父SKU后仍保留在结果中。筛选在分页前应用，默认50组一页，子体明细默认折叠。

## 未合成变体

- 在最新Listing中出现、且该店所有国家均没有有效父ASIN的子ASIN，可按中文品名识别为“未合成变体”。某个国家已经有有效父体时仍归原父体组；运营表里有但最新Listing未出现的ASIN不凭缺失推断为无父体。
- 以SKU末尾数字为编号，数字前完整前缀及编号位数必须一致，按数字升序归组。缺号或品名不达标时断组；从当前SKU另起一组。同SKU多个国家或ASIN不重复参与连号判断。
- 品名统一NFKC全半角、英文大写及连续空白（合为一个空格）；沿用忽略末尾小数价格括号、【K】等字母标记。颜色、尺寸、数量、型号和包装均参与完整品名比较。标准库SequenceMatcher关闭autojunk，以未四舍五入的ratio严格大于0.8判定；按SKU升序确定比较方向。
- 新成员必须与组内每个成员都超过80%，仅相邻相似不能传递合并。名称完全相同也可归组，颜色／尺寸差异不再是必需条件。同一SKU在候选中有多个互相矛盾的规范品名或没有有效品名时，跳过自动识别；跳过的编号不能填补断号。
- 每组至少两个SKU、两个不同子ASIN；同一ASIN多SKU不增加变体数。通用品名按SKU数字顺序逐个求最长公共子序列，多解优先保留较小编号SKU中靠前的字符；保留中间及后部共同信息，清理空括号、重复及首尾分隔符，英文使用规范后的大写。无法取得名称时显示“品名待归纳”。子体原文仍完整保留。
- 国家、父ASIN、原语言变体属性的对应关系继续保留；原表属性为空时仍可使用现有颜色／尺寸后缀解析补充展示，但不将其作为归组条件。
- 未合成组不生成虚假的父ASIN，仍可填写父SKU。后续出现真实父体关系时，按已有子ASIN关联保留人工记录，合并拆分冲突规则相同。

## 店铺与虚拟2件装

- 只在变体管理排除NFKC／大小写归一后匹配VMP_.+_2_PK的MSKU，先排除再执行关系连接、计数、命名、代表图和未合成识别；其它件数不按此规则排除。原Listing、价格及Rating数据保留。
- 店铺优先以MSKU＋ASIN精确匹配运营表，复用extract_operational_store_codes，与首页／销量看板同样显示ZXU等代码。明确多店关联保留各店关系；无法关联时取SKU开头第一位数字前的连续英文字母，如ZXU261101CQT001→ZXU；仍不能识别时归“未识别店铺”。根据SKU前缀识别的行提供来源提示。
- stores为逗号分隔店铺多选，店铺之间取并集，与状态、开发员及已提交搜索共同过滤，分页前计算总数。完整店铺组及开发员选项在筛选前构建，重置恢复全部店铺。
- 子体销量继续按运营MSKU＋ASIN原口径关联，不从SKU前缀生成或拆分销量。跨国家同店归并不会重复累计。

## 父SKU与关系变动

SQLite新增`variant_parent_skus`，保存组成员、父SKU和待确认候选，新增可空store_code，独立于Listing滚动历史。旧记录store_code为空，代表未分店历史；新组键及保存记录包括店铺。父SKU去首尾空格，同店当前不同组的唯一性比较按NFKC及大写归一。

按店记录仅与同店当前组共享父ASIN或子ASIN时建立关联，不同店可独立填写或复用相同父SKU。旧未分店记录在全量店铺上下文中关联：唯一匹配店铺继承，匹配多店则各店显示“历史父SKU（店铺待确认）”候选，逐店确认。唯一可确定的关系保留父SKU；已有父SKU的组拆分、不同父SKU合并、或休眠组返回造成重复时标为待确认，页面行内明确显示“父SKU待确认”。可以选择旧候选、填写新值或明确清空。仅查看不写库；人工保存时在事务内只固化当前店铺关系，保留其它店铺与旧未分店记录；已有店铺记录优先于旧历史，明确清空后不会被旧值回填。保留其他分支的待确认候选及暂时不在源文件中的记录，避免已解决冲突反复出现。

其它店铺提示按非虚拟子ASIN交集计算，来源为已确认非空的父SKU（包括保留的休眠店铺记录），显示店铺、父SKU及匹配子体数；部分重合明确标注匹配范围。提示在全量范围构建，不受店铺筛选和分页限制。未确认候选不当作已确认参考。行内编辑可引用后修改，只有点击确定才保存到当前店铺。

`GET /api/variants`接受search、stores（逗号分隔）、status（all／filled／empty／pending／unassembled）、developers（逗号分隔）、page、page_size（1～200），其中unassembled按关系类型过滤，pending继续兼容父SKU待确认查询；返回店铺／开发员选项、快照日期、关系revision、完整组列表及分页；组包含store_code、store_inferred、legacy_assignment、other_parent_skus、relation_kind、product_name和child_asin_count，子体增加product_name。`PUT /api/variants/{group_key}/parent-sku`接受parent_sku和读取时的revision；关系、运营源、归组算法版本或其他人工记录改变返回409，同店当前重复父SKU也返回409。Listing上传与父SKU保存共用进程锁，SQLite事务保护并发保存。前端保留失败草稿、提交锁；保存成功后刷新失败单独提示已保存。

独立页面使用`?page=variants`，导航键`products:variants`。激活版本依赖reports、dashboard和variants域，覆盖Listing、运营、图片及人工数据；页面保留挂载和请求取消保护。父SKU在原值／待填写处点击铅笔，用Ant Popover小框编辑并取消／确定；忙碌时锁定输入、关闭与重复提交，离开页面时隐藏浮层，不另设操作列。不引入依赖。

## 加载与保存性能

- 按Listing与运营源revision缓存关系分组、运营指标和名称识别，图片展示另含图片映射文件revision；各层最多保留两个版本。筛选、分页、重复进入和父SKU保存复用未变化的源数据，源文件变化后重新计算，首次冷加载仍需构建。
- 父SKU、冲突候选、继承关系和跨店铺参考不缓存，每次读取最新SQLite记录。保存前先准备源数据，事务内继续校验revision、店铺唯一性及当前源版本，提交前再检查源变化；保存路径跳过只用于列表的跨店铺提示计算。
- 并发冷请求共用现有Listing锁，避免重复构建。缓存只包含源数据，人工保存不会污染缓存，明确清空、冲突确认、筛选后的总数与旧响应保护沿用现有语义；无API或数据库结构变更。

## 验收边界

测试、浏览器必须使用隔离data/config/SQLite，不导入真实环境的backend.main。组数量随运营源和店铺关系更新变化，不能将本机数量当作固定验收值。本机缺附件时仅该外部样例测试跳过，其余逻辑使用固定夹具。命令使用run_bounded.py设85秒硬截止。

浏览器使用隔离样例和示意图，不代表全部生产业务的端到端验收。后端算法修改需重启应用加载；初始化幂等加列兼容store_code，历史记录不自动改写。内部交接材料不随源码公开。
